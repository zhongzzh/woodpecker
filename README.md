# woodpecker（啄木鸟）—— 数学库函数提测测试自动化

> 状态：**方案讨论阶段，尚未实现**。所有结论以 `docs/` 下文档为准。
> 项目名由来：啄木鸟逐棵树捉虫补漏，正是测试员给代码找 bug、补测试的比喻；与 parrot（文档测试）同属鸟类系列。

## 这个项目解决什么问题

测试组每周收到开发的"周提测"邮件（任务类型：新增函数 / 性能优化 / 算法优化），
对每个任务要做两件事：

1. **功能测试**：以函数文档为准，核对开发提交的单元测试覆盖是否有遗漏，
   补写缺失的测试用例（开发已写的内容一律不动）；
2. **性能测试**：阅读 MR 中的性能报告，按给定标准判定是否通过。

本项目把这个流程做成半自动：**人工提取任务输入 → 工具完成分析 → 输出一份总的分析报告**。

## 边界（硬约束）

- 只读分析：不修改、不提交开发的任何代码与文档。
- 补充的测试代码只出现在分析报告中，是否落库由人决定。
- 输入由人工从邮件/MR 中提取，不做邮件自动解析（至少现阶段不做）。
