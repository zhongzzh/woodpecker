## A. 输入契约：一个任务到底给工具什么？【字段已定 →D8，载体待定】

字段已拍板（D8），任务卡只剩三样，其余工具自己找：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 任务名 | 新增 surfaceArea 函数 | 含函数名与任务类型 |
| 代码仓库/MR 链接 | …/merge_requests/330 | 分支名、单测代码、性能报告（note）都从这里推导 |
| 文档链接 | 仓库内路径或另一 MR 链接 | 新增函数的文档是新建的，工具无法凭空猜，必须给 |

工具侧的推导链（用户描述的流程）：
文档链接 → 找到 md 文档内容；MR 链接 → 查源分支 → clone/checkout →
在该分支上找单元测试代码；性能报告就在 MR 的 note 里。

**仍待拍板：**

1. 任务卡载体：Markdown 模板文件？还是对话里直接口述？
   （初步倾向：`tasks/<期号>/<函数名>/task.md`，人填模板、工具读文件——可追溯、可重跑。）
2. 从 MR 链接查源分支需要登录态 → 依赖 playwright MCP（见 F 项）；
   MCP 不可用时的降级方案：人工把分支名补进任务卡。

## C. 实现形态：skill / subagent / workflow / 纯脚本【想清楚再选】

比较维度：

| 维度 | 关键问题 |
| --- | --- |
| 交互性 | 哪些步骤必须人确认？（例：缺口清单先人审，通过后再生成用例？） |
| 上下文量 | 一个函数的文档+测试+相关源码有多大？单个对话装不装得下 |
| 并行度 | 一期约 5 个任务，要不要并行跑 |
| 可复现 | 换台机器/换个实习生，能不能照着跑出同样的东西 |
| 失败恢复 | 中途断了，能不能只重跑一个任务而不从头来 |

**初步倾向（未定，仅供讨论）：**

- 确定性步骤（clone/checkout、定位文件、收集材料）→ 脚本，稳定可靠；
- 分析步骤（读文档、找覆盖缺口、写用例、判性能）→ 模型做；
- 载体选型（skill 还是 agent 还是 workflow）等 A、B 定型后再决定——
  只要"输入任务卡、输出报告"这个接口稳定，换载体成本很低，不必现在锁死。

## E. 要不要在本机真的跑？【方向已明，细节待定】

已明确（→D9）：MATLAB 作为补测 baseline **有用**——补写用例时没有标准答案，
需要 MATLAB 的计算结果来对照 Julia（Syslab）的输出，否则 expected 无从写起。
即方向上至少到"档位 3"（静态 + baseline），但"有时候有用"，不是每个用例都强制跑。

三个档位（保留作参考）：

1. **纯静态**：只读文档+测试代码做覆盖分析，补充用例只做静态检验（不运行）。
2. **静态 + 回归**：额外在本机跑一遍开发已有的测试。
3. **静态 + 回归 + baseline**：补充用例的 expected 经 MATLAB baseline 验证后回填。

**仍待确认：** 用户日常怎么跑这些库的测试（命令、registry、Syslab 版本）；
哪些函数 MATLAB 有对应物、哪些没有（没有对应物时 expected 从哪来）。
