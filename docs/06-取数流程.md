# 06 取数流程（如何拿到分析所需的材料）

> 用户 2026-07-14 口述流程 + 用 partialcorri（TyStatisticsCore.jl，MR !472）实走验证通过。
> 这份文档就是未来"确定性步骤脚本"的规格。

## 输入

任务卡三要素（D8）：任务名（含函数名）、代码仓库/MR 链接、文档链接（文本链接）。

## 流程

### 1. 仓库就位

- 克隆位置固定：`C:\Users\TR\Desktop\doc\<库名>.jl`
- **已存在则不重复克隆**（该目录下现有 TyStatisticsCore.jl、TyMathCore.jl、
  TyComputationalGeometry.jl、TyGraphTheory.jl 等；remote 走 SSH：
  `ssh://git@git.tongyuan.cc:222/syslab/packages/math/<库名>.jl.git`）
- 操作前先 `git status` 确认工作区干净，避免覆盖用户未提交的改动。

### 2. 切分支、拉最新

- 源分支名从 MR 页面读（playwright；页面上"requested to merge <源分支> into main"）。
  例：!472 → `lius/partialcorri_optim_3`
- `git fetch origin` → `git checkout <源分支>` → `git pull`

### 3. 定位单元测试

优先级顺序：

1. **性能报告/提交信息的路径指引**：报告详细表的 `git_file` 列、以及提交信息
   （形如 `Performance:benchmark/...&lt;函数名&gt;:4:...`）都带路径；
2. **按约定直接找**：`test/<大类>/<小类>/<函数名>.jl`；
3. 兜底：全仓 `find/grep 函数名`。

### 4. 定位性能报告

MR 讨论区最新一条机器人 note（D12/D14），playwright 抓取，方法见 05 文档。

### 5. 定位函数文档（新增函数）

文档统一在**独立的文档仓库** syslab-docs-2.0（注意：目标分支是 **develop**，不是 main）：

- 本地位置：`C:\Users\TR\Desktop\doc\syslab-docs-2.0`（已存在，不重复克隆；
  remote `ssh://git@git.tongyuan.cc:222/syslab/syslab-docs-2.0.git`）
- 任务卡的"文档链接"是该仓库的 MR，从 MR 页面读源分支 → fetch/checkout/pull
  （切分支前若工作区有未提交改动，先 `git stash` 暂存，勿丢弃）；
- 定位 md 的**首选方法**：`git diff --name-status origin/develop...HEAD`，
  状态为 `A`（新增）的 `.md` 就是函数文档；同 MR 里状态 `M` 的几个 md 是目录索引登记，
  不是分析对象；
- 兜底：`syslabHelpSourceCode/projects/<Ty项目名>/Doc/.../<函数名>.md` 按名查找。

实测例（MR !3761，polydiv，分支 lius/polydiv-new）：
`syslabHelpSourceCode/projects/TyMath/Doc/TyMath/ElementaryMath/Polynomials/polydiv.md`

文档 md 的固定结构（覆盖分析的依据）：
`# 函数名` / `## 语法` / `## 说明` / `## 示例` / `## 输入参数` / `## 输出参数` / `## 另请参阅`

## TyStatisticsCore.jl 的实测目录约定（03-D 第一个数据点）

```text
test/<大类>/<小类>/<函数名>.jl            # 单测主文件，一函数一文件
test/.../<函数名>_data_N.jl               # 测试数据（被主文件 include）
test/.../<函数名>_ai_data.jl              # AI 生成的测试数据（已有先例！）
test/runtests.jl                          # 用 TyAPI 的 @test_package 自动发现，无手工 include 清单
benchmark/<大类'>/<小类>/<函数名>/PerformanceTest/PerformanceTestN/
    PerformanceTestN.jl + PerformanceTestN.m   # 同一用法的 Julia 版与 MATLAB 版成对出现
```

注意：benchmark 的大类名与 test 的不一致（`DescripitiveStatisticsandVisualization`
vs `DescriptiveStatistics`），不能想当然互推，以实际查找为准。

## 单测文件内部的既有写法（对补测很重要）

partialcorri.jl 实测：

- 每个用法一个 `@testset "函数名_场景"`，**testset 上方注释里就是对应的 MATLAB 原代码**；
- 已存在 AI 辅助测试的完整先例：`AI_assert_matlab_equal(actual, expected; atol=1e-12, rtol=1e-12)`
  辅助函数 + `_ai_data.jl` 数据文件——expected 来自 MATLAB 运行结果，回填进数据文件，
  与 D9（MATLAB 作 baseline）完全同构。补写用例可直接沿用这套模式。
