## 1. 核心洞察：只有一步需要 AI

已验证的管线拆解后，各环节的性质：

| 环节 | 性质 | 实现 |
| --- | --- | --- |
| 克隆/切分支/拉取（06 文档流程） | 确定性 | 脚本（git 命令封装） |
| 读 MR 页面：源分支名、当前函数最新性能报告 note | 确定性 | playwright 或 GitLab API（见问题 4） |
| 定位文档 md / 单测 jl / benchmark | 确定性 | 脚本（MR diff + 目录约定三级定位） |
| 性能判定（D13/D15/D16） | 确定性 | 脚本（纯数值，逐用法出明细表） |
| **覆盖分析（文档 vs 单测 → 报告）** | **需要 AI** | 提示词 v1 + 两个文件文本 → 一次 LLM 调用 |
| 报告拼装/渲染 | 确定性 | 脚本(md → HTML) |

→ 这是"单次 LLM 调用 + 确定性工作流"的形态，不需要复杂的多轮 agent。架构因此简单、稳定、可测。

## 2. 架构（三层）

```text
┌────────────────────────────────────────────┐
│  UI 壳（本地网页，浏览器打开）               │
│  任务卡表单 → 进度展示 → 报告查看/历史        │
└──────────────┬─────────────────────────────┘
               │ 本地调用
┌──────────────▼─────────────────────────────┐
│  编排后端（Python）：按顺序跑管线、管理任务目录 │
├────────────────────────────────────────────┤
│ 确定性模块                    │ AI 模块      │
│ repo.py   git 取数(只读)      │ analyze.py  │
│ mr.py     MR页面→分支/报告    │ 提示词v1 +   │
│ locate.py 定位md/jl/benchmark │ md+jl 文本   │
│ perf.py   D13性能判定         │ → 覆盖报告   │
│ report.py 汇总渲染            │ (一次调用)   │
└────────────────────────────────────────────┘
```

**硬约束在代码层强制**：repo.py 只实现 clone/fetch/checkout/pull/stash，**不写 push/commit 函数**（D18 只读边界物理不可违反）；报告只写到 woodpecker 自己的 `tasks/` 目录，被测仓库零改动。

## 3. MVP 界面（单页三区）

```text
┌─ woodpecker 提测分析 ─────────────────────────┐
│ 任务名   [新增 polydiv 函数            ]      │
│ 代码 MR  [https://git.tongyuan.cc/...856]     │
│ 文档 MR  [https://git.tongyuan.cc/...3761]    │
│                          [ 开始分析 ]         │
├───────────────────────────────────────────────┤
│ 进度: ✔取数 ✔定位 ⟳AI覆盖分析 ○性能判定 ○汇总  │
│ 日志: checkout lius/polydiv_new ... ok        │
├───────────────────────────────────────────────┤
│ [报告] [历史任务▾]                            │
│  ── polydiv 覆盖分析报告（渲染的 md）──        │
│  ...                        [下载 .md]        │
└───────────────────────────────────────────────┘
```

- 存储即目录：每次运行落 `tasks/<函数名>-<日期>/`（材料快照 + 报告），历史列表就是读目录，无数据库。
- 出错处理：每步失败给人话提示（如"分支不存在，请检查 MR 链接"），可单步重跑。

## 4. 技术选型（建议 + 备选）

| 决策点 | 建议 | 备选 | 说明 |
| --- | --- | --- | --- |
| UI 壳 | **本地 Web**（Python: Streamlit 或 FastAPI+页面），做 `启动.bat` 双击即开 | Tauri/Electron 桌面程序 | 本地 Web 开发最快、和 Python 后端一体；桌面打包体验好但成本高，流程稳定后再议 |
| AI 调用 | **当前配置单通道**：网页选择 OpenAI 或 Anthropic 兼容协议、端点、Key 和模型 | — | 同一配置失败最多尝试三次；不切换 CLI、协议或模型，最终失败写入报告并保留已完成结果 |
| MR 页面读取 | **申请 GitLab 个人 Access Token**（read_api 权限）：读源分支+note 变成两个 HTTP 请求，快且稳 | playwright-python 带持久化登录 | token 从个人设置页自助生成，不需要管理员；playwright 方案对小白多一步"首次登录浏览器" |
| 模型 | 使用网页 AI 设置当前选定模型 | — | 覆盖分析质量敏感；任务过程中不自动更换模型 |

**不采用**的形态及原因：云端托管 agent（Managed Agents 等）——内网 GitLab 不可达、代码不出内网；纯 Claude Code skill——对小白仍是命令行，不满足本次需求（但管线模块可两边复用）。

**数据外发范围说明**（合规确认点）：在线 MR 模式只向 LLM 发送**函数文档 md + 单测 jl 的文本**（与现在人工贴给 AI 的范围一致），结构化性能报告继续由本地脚本演算。使用“本地材料”且主动粘贴自由格式性能报告时，该段报告原文也会发送给 LLM 做解释；留空则完全不发送性能数据。仓库其余代码不外发。
