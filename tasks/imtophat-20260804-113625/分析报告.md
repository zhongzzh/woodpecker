- Markdown 文档声明 I 可以是“任意维度”图像，但公开实现只提供二维 `AbstractMatrix` 和三维 `AbstractArray` 方法，不支持一维及四维以上数组。

- 文档未说明 SE 是否允许空矩阵；实现对空 SE 调用 `maximum` 时会产生异常。
- 文档未说明 SE 的尺寸、奇偶性、锚点位置及其与 I 尺寸之间的约束。
- 实现签名接受任意 `Integer` 元素类型的 SE，而 Markdown 只声明 UInt8、Bool，公开文档与实际可分派类型范围不一致。

- 示例通过 `imread` 加载图像并通过 `strel` 创建 SE，但没有展示或断言二者的具体类型，无法用于确认示例是否严格符合参数类型表。

### 覆盖缺口与优先级

**高优先级**

- Bool 二值 I 未覆盖。现有 Bool 数组全部位于第二参数位置，不能证明 Bool 图像输入的转换、运算和 Bool 输出路径；应增加确定性 Bool 图像、调用及输出类型、尺寸和二值性质断言。
- UInt8 数值 SE 未覆盖。`strel` 结果没有类型断言，不能推断它是 UInt8；应显式构造只包含 0 和 1 的 UInt8 矩阵，并与等价 Bool SE 的结果比较。
- 三维 I 未覆盖。实现具有独立三维分派和逐切片处理逻辑，二维测试无法覆盖该路径；应增加数值三维图像和 Bool 三维图像，并验证类型、尺寸及逐切片一致性。
- “任意维度”契约与实现冲突。一维及四维以上输入既无测试，也没有适用方法；应先决定是扩展实现还是将文档收窄为二维、三维，再按最终契约补测。

**中优先级**

- 五种数值 I 的现有断言只检查输出类型和尺寸，不能证明形态学结果正确；应使用可信 baseline 或独立数学参考实现校准固定输入的像素结果。
- 大量测试使用未设随机种子的 `rand`，输入内容不稳定，且 Bool SE 理论上可能退化；应采用固定矩阵或固定随机种子提高可重复性。
- SE 的值域约束未形成公开测试。实现拒绝包含非 0、1 的整数 SE，但文档没有声明；明确接口契约后，应补充成功路径或异常断言。
- 文件示例没有输入类型断言。应对 `src` 和 `kernel` 增加类型、维度确认，避免图片解码器或 `strel` 返回类型变化后覆盖结论失真。

**低优先级**

- `1 × 1` SE 只有类型和尺寸断言，属于单点弱证据；可增加固定输入并验证单位结构元素产生全零顶帽结果。
- 单行和单列测试被命名为“向量”，但实际是二维 Matrix；若接口预期支持真正的一维 Vector，应先修正文档或实现，再增加真实 Vector 用例。
- SE 的空矩阵、偶数尺寸、非对称结构元素和大于图像尺寸的行为均未明确；这些项目应在文档补充约束后再建立边界测试。

        @test result_3d isa AbstractArray{UInt16,3}
